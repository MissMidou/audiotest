# Data Model: 微信扫码听音频二维码

**Phase 1 产出** | 实体与数据结构，供实现与契约对齐。

---

## 1. 构建时数据（构建脚本产出）

### 1.1 音频目录清单（Manifest）

构建脚本扫描源文件夹后生成的一份清单，供前端 `index.html` 加载并渲染列表。建议格式（如 `manifest.json`）：

| 字段 | 类型 | 说明 |
|------|------|------|
| `items` | `array` | 音频项数组，顺序与构建时扫描顺序一致（可按文件名排序） |
| `generatedAt` | `string` (ISO 8601) | 可选，构建时间戳 |

### 1.2 音频项（Audio Item）

清单中每一项对应一首可播放的音频。

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | `string` | 唯一标识，建议用文件名或相对路径的稳定 slug（如 `guyongzhe`、`06-zuweidadezuopin`） |
| `label` | `string` | 展示名称，可与文件名一致或由文件名推导（如去掉扩展名、空格替换） |
| `url` | `string` | 部署后的音频 URL 相对路径（如 `audio/孤勇者.flac`），前端据此加载 `<audio src="...">` |
| `filename` | `string` | 可选，原始文件名（如 `孤勇者.flac`、`06. 最伟大的作品.flac`） |

**校验**：
- `items` 非空时至少有一项；构建时若扫描结果为空，应报错或警告（见 research）。
- `url` 在部署后必须可访问；构建产物中需包含对应音频文件。

## 2. 运行时状态（前端 H5 页面）

### 2.1 页面状态

| 状态 | 说明 |
|------|------|
| `loading` | 正在加载页面或目录数据（manifest/内联数据） |
| `ready` | 目录已加载，列表已渲染，用户可选择播放 |
| `error` | 加载失败（超时或网络错误），展示错误提示 |
| `empty` | 目录数据为空数组，展示“暂无可播放音频” |

### 2.2 播放状态（单曲）

| 状态 | 说明 |
|------|------|
| `idle` | 未播放 |
| `playing` | 正在播放 |
| `paused` | 已暂停 |
| `error` | 加载/播放失败，展示该曲目的错误提示 |

状态转换：`idle` → `playing` ↔ `paused`；任一状态可 → `error`。切换曲目时当前曲目回到 `idle` 或 `paused`，新曲目进入 `playing`。

---

## 3. 实体关系（概念）

- **二维码** → 对应一个 **H5 目录页 URL**（部署后的 `index.html` 的绝对 URL）。
- **H5 目录页** → 加载并展示 **音频目录清单**（manifest）；每项对应 **音频文件**（部署在 `audio/` 等路径下）。
- **用户** → 在目录页选择 **音频项** → 触发 **播放**（单例：同一时刻仅一首在播）。

无持久化存储；无用户账号或会话。清单与音频文件均为构建时确定、部署后只读。
